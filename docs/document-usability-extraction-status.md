# Document Usability & Extraction

Status: **READY.** The manual responsive matrix is complete. Fresh full verification passed, and final independent review of the current diff and status evidence returned PASS with no findings.

## Implemented scope

- Structured generic document Action Suggestions with short evidence/context and semantic date relations. The application resolves dates only from reliable Item/document anchors. Suggestions are not created automatically, accepted Actions use the normal Action model, and obvious same-Item duplicates are filtered using existing simple title normalization.
- Extraction values are classified as new, identical, or conflicting. New values are selectable, identical values remain visible in a secondary section, and conflicts default to keeping the current value. Replacements require explicit selection. Field writes and Actions are applied atomically; History records only committed changes.
- Global notification time is stored as local `HH:MM`, defaults to the previous effective `08:00`, and is evaluated by a minute-level scheduler. Existing delivery idempotency and ntfy/Slack dispatch paths are retained. Action-specific reminder schedules were not added because the existing model has no such override.
- Upload selection displays the actual filename, type and size, changes the picker control to “Datei ändern”, and keeps replacement separate from upload. Upload/analysis pending states are announced and controls disable while submitting.
- Ready Actions consistently show “Erledigen” and “Überspringen” as primary actions; scheduling is secondary. Dependency/readiness rules remain intact.
- DE/EN strings, migration, tests, and concise user-facing History follow existing project patterns. No unrelated product area was redesigned.
